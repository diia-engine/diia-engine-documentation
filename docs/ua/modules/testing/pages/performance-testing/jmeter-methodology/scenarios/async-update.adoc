= Сценарій "Внесення змін в масову сутність"
include::platform:ROOT:partial$templates/document-attributes/default-set-ua.adoc[]

:sectlinks:

Цей документ описує технічний процес розробки та автоматизації сценарію навантажувального тестування для функціоналу "Внесення змін в масову сутність". Сценарій імітує повний життєвий цикл обробки бізнес-процесу, що включає ініціацію процесу та очікування його завершення.

[#overview]
== Огляд сценарію
Мета цього сценарію — імітувати поведінку офіцера, який ініціює бізнес-процес, що виконується асинхронно, та очікує його завершення шляхом періодичного опитування стану.

Схема роботи сценарію:

. *Ініціалізація:* Налаштування глобальних змінних та функцій.
. *Авторизація:* Проходження повного циклу авторизації на офіцерському порталі.
. *Ініціація бізнес-процесу:* Запуск нового екземпляра бізнес-процесу.
. *Асинхронне очікування:* Періодичне опитування стану процесу до його завершення.
. *Вихід:* Завершення сесії користувача.

[#csv-users-data]
=== CSV Data Set Config (Users Data)

*CSV Data Set Config* — це конфігураційний елемент JMeter, який дозволяє читати дані з CSV-файлу та використовувати їх як змінні у тест-плані. Це дозволяє легко параметризувати запити, використовуючи різні набори даних для кожного потоку або ітерації.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[CSV Data Set Config]

image:testing:jmeter-methodology/async-update/145123606.jpg[]

**Значення для CSV Data Set Config:**

* *Filename:* `${testDataDir}/mock-users.csv`
* *File Encoding:* (порожнє, використовується системне)
* *Delimiter:* `,`
* *Variable Names:* `userName,fullname,edrpou,drfo`
* *Ignore first line:* `false` (оскільки файл не містить заголовка)
* *Allow quoted data:* `false` (чи потрібно інтерпретувати дані, взяті в лапки, як окремі значення)
* *Recycle on EOF:* `false` (не починати знову після закінчення файлу)
* *Stop Thread on EOF:* `true` (зупинити потік, коли дані закінчаться)
* *Sharing Mode:* `All threads` (кожен потік отримує унікальні дані)

[#create-slurp-sampler]

Цей *JSR223 Sampler* створює глобальну функцію `slurp` (використовуючи `JsonSlurper` з Groovy), яка дозволяє легко парсити JSON-рядки. Ця функція зберігається у `props` (глобальні властивості JMeter), що робить її доступною для всіх потоків та Test Fragment-ів.

image:testing:jmeter-methodology/async-update/145123739.jpg[]

* *Name:* `Create slurp`
* *Language:* `groovy`
* *Script:*
+
[source,groovy]
----

def slurp = { text ->
    new JsonSlurper().parseText(text.toString())
}

props.put('slurp', slurp)
SampleResult.setIgnore()
----

****** *JSR223 PreProcessor*
+
Цей *JSR223 PreProcessor* оновлює `xsrfToken` у змінних JMeter, витягуючи його з `Cookie Manager`. Це необхідно, оскільки XSRF токен може змінюватися після деяких запитів.

*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import org.apache.jmeter.protocol.http.control.CookieManager

CookieManager manager = sampler.getCookieManager()
if (manager != null) {
    for (int i = 0; i < manager.getCookieCount(); i++) {
        if (manager.get(i).getName().equals("XSRF-TOKEN")) {
            def latestToken = manager.get(i).getValue()
            vars.put("xsrfToken", latestToken)
            log.info("=== [XSRF SYNC] Оновлено токен із Cookie Manager: " + latestToken)
            break
        }
    }
} else {
    log.warn("Cookie Manager не знайдено!")
}
