= Видалення користувачів з Keycloak
include::platform:ROOT:partial$templates/document-attributes/default-set-ua.adoc[]

:sectlinks:

Цей документ описує технічний процес розробки та автоматизації сценарію видалення тестових користувачів з Keycloak. Це критичний крок для підтримки стабільності тестового середовища (Environment Cleanup), що дозволяє уникнути конфліктів при повторному запуску навантажувальних тестів.

[#overview]
== Огляд сценарію
Мета цього сценарію — гарантувати, що перед кожним прогоном навантажувальних тестів реєстр користувачів Keycloak знаходиться у «чистому» стані.

Схема роботи сценарію:

. *Авторизація:* Отримання Bearer Token через Keycloak Admin API для виконання адміністративних операцій.
. *Підготовка черги на видалення:* Ініціалізація і заповнення черги ID користувачів на видалення.
. *Видалення:* Виконання `DELETE` запиту до Keycloak Admin API для кожного цільового користувача.

[#prerequisites]
== Підготовка до розробки
Поточна документація описує процес створення `**.jmx*` сценарію на прикладі GUI Apache JMeter 5.6.3.
===
[NOTE]
====
Всі компоненти сценарію описані нижче у порядку відображення у середовищі JMeter. Тому, ознайомлюючись з елементами типу Test Fragment, слід мати на увазі, що порядок їх використання в процесі може відрізнятися від порядку розміщення у списку даної інструкції.
====

Завдяки цьому *Grafana* не показує кожен тест як окрему історію, а збирає їх разом під одним ідентифікатором (`application`).

[#http-request-defaults]
=== HTTP Request Defaults

*HTTP Request Defaults* — це конфігураційний елемент (Configuration Element) у JMeter, який виконує роль "глобального шаблону" для всіх HTTP-запитів.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[HTTP Request Defaults]

image:testing:jmeter-methodology/delete-keycloak-users/141150130.jpg[]

**Як це працює:**

. *Сфера дії (Scope):* Елемент діє на всі запити, що знаходяться "під ним" або на тому ж рівні в дереві тест-плану.

. *Перевизначення (Override):* Якщо в самому HTTP Request вказати значення (наприклад, інший шлях /login замість дефолтного /), JMeter надасть пріоритет налаштуванням конкретного запиту, ігноруючи дефолтні.

**Значення для HTTP Request Defaults**

* *Protocol:* `${protocol}`
* *Server Name or IP:* `${keycloack_url}`
* *Port Number:* `${port}`

[TIP]
====
Завжди розміщуйте *HTTP Request Defaults* на рівні "*Test Plan*" (якщо налаштування стосуються всього тесту) або на рівні конкретної "*Thread Group*" (якщо потрібні різні налаштування для різних груп користувачів). Це найкращий спосіб уникнути "магічних значень", які потім важко знайти та виправити.
====

[#set-up]
=== setUp Thread Group

*setUp Thread Group* у JMeter виконується *один раз перед запуском основних Thread Group* і використовується для підготовчих операцій (preconditions / test data setup).

У даному сценарії він виконує підготовчий етап перед основним тестом:

. Ініціалізує структуру (чергу / контейнер) для збереження ID користувачів, які будуть видалятися в тесті.
. Виконує запити до Keycloak для отримання списку користувачів за заданими умовами (фільтрація/пошук).
. Зберігає отримані user ID у чергу для подальшого видалення основними потоками.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Threads (Users)] -> kbd:[setUp Thread Group]

image:testing:jmeter-methodology/delete-keycloak-users/141160625.jpg[]

**Значення для setUp Thread Group**

* *Name:* setUp Thread Group
* *Action to be taken after a Sample error:* Continue
** помилки не зупиняють підготовчий етап, щоб не зірвати весь тест через одиничний збій
* *Number of Threads (users):* 1
** виконується одним потоком (послідовна ініціалізація)
* *Ramp-up period (seconds):* 1
** швидкий старт без розподіленого навантаження
* *Loop Count:* 1
** виконується лише один раз

[#init-queue]
==== Init queue (JSR223 Sampler)

*JSR223 Sampler* — це елемент Apache JMeter, який виконує власний скриптовий код для генерації або обробки тестових даних. Він дуже універсальний і дозволяє імітувати логіку, яку неможливо обробити стандартними запитами (наприклад, семплером HTTP-запитів), використовуючи такі мови програмування, як Groovy, JavaScript або Java.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[JSR223 Sampler]

image:testing:jmeter-methodology/delete-keycloak-users/141162509.jpg[]

**Значення для setUp Thread Group**

* *Name:* Init queue
* *Language:* groovy
* *Script:*
+
[source,groovy]
----
import java.util.concurrent.ConcurrentLinkedQueue
props.put("usersQueue", new ConcurrentLinkedQueue<String>())
vars.put("keepFetching", "true")
----

[IMPORTANT]
====
Створюється `*ConcurrentLinkedQueue*` — потокобезпечна (thread-safe) черга для спільного використання між потоками JMeter.
====

[IMPORTANT]
====
`*props*` — це *глобальний scope* JMeter. Змінні в props: видимі всім Thread Group, доступні всім потокам, живуть протягом усього тесту.
====

[TIP]
====
`*vars.put("keepFetching", "true")*` — створюється звичайна локальна змінна потоку. Ця змінна потрібна для керування циклом, наприклад поки `keepFetching == true` -- цикл продовжується.
====

[#get-token-controller]
==== Get token (Module Controller)

Module Controller — це елемент логіки JMeter, який дозволяє викликати інший фрагмент коду (Test Fragment), що знаходиться в цьому ж тест-плані. Це ключовий інструмент для дотримання принципу DRY (Don't Repeat Yourself).

Замість того, щоб дублювати логіку отримання токена в setUp Thread Group та основній Thread Group, ми створюємо її один раз у Test Fragment, а звідси лише "посилаємося" на неї.

. Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[Module Controller]
. У вікні налаштувань розгорніть дерево тест-плану і виберіть цільовий Test Fragment, натиснувши на кнопку kbd:[Find target element].

image:testing:jmeter-methodology/delete-keycloak-users/142091923.jpg[]

[NOTE]
Детальний опис того, як саме налаштований запит за токеном і як обробляється відповідь, дивіться у <<#test-fragment-get-token, розділі "Get token (Test Fragment)">>.

[#while-controller-fetch-users]
==== While Controller (Збір користувачів)

Використовується для циклічного збору ID користувачів з Keycloak, доки не будуть отримані всі користувачі, що відповідають критеріям пошуку.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[While Controller]

image:testing:jmeter-methodology/delete-keycloak-users/146111805.jpg[]

*Condition (function or variable):*

`${__groovy(vars.get('keepFetching') == 'true')}`

Цикл триватиме доти, доки змінна `keepFetching` має значення `true`.

***** *Counter*
+
*Counter* — це конфігураційний елемент, який генерує послідовні числа, починаючи з заданого стартового значення. У цьому випадку він використовується для керування параметром `offset` при пагінації запитів до Keycloak.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[Counter]
+
image:testing:jmeter-methodology/delete-keycloak-users/146111850.jpg[]
+
*Start:* `0`
+
*Increment:* `1000`
+
*Reference Name:* `offset`
+
*Track Counter Independently for each User:* `false`

***** *Search users (HTTP Request)*
+
Цей запит виконує пошук користувачів у Keycloak за певними критеріями та з використанням пагінації.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[HTTP Request]
+
image:testing:jmeter-methodology/delete-keycloak-users/146111935.jpg[]
+
*Method:* `GET`
+
*Path:* `/auth/admin/realms/${realm}/users`
+
*Parameters:*
** `search`: `perf-test-officer-` (префікс для пошуку тестових користувачів)

** `first`: `${offset}` (поточне зміщення для пагінації)
** `max`: `1000` (максимальна кількість користувачів за запит)
** `briefRepresentation`: `true` (отримати скорочене представлення користувачів)

****** *JSON Extractor (fetchedIds)*
+
*JSON Extractor* використовується для витягнення ID користувачів з JSON-відповіді.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Post-Processor] -> kbd:[JSON Extractor]
+
image:testing:jmeter-methodology/delete-keycloak-users/146112043.jpg[]
+
*Names of created variables:* `fetchedIds`
+
*JSON Path expressions:* `$[*].id`
+
*Match No.:* `-1` (витягти всі відповідності)
+
[TIP]
====
JMeter створює в результаті змінну *fetchedIds_matchNr* - яка містить кількість знайдених відповідностей та змінні *fetchedIds_XXX*, де XXX = 1..1000, які містять знайдені результати (ID користувачів)
====
****** *JSR223 PostProcessor*
+
Цей *JSR223 PostProcessor* обробляє отримані ID користувачів, додає їх до глобальної черги `usersQueue` та перевіряє, чи потрібно продовжувати збір користувачів.
+
image:testing:jmeter-methodology/delete-keycloak-users/146112137.jpg[]
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
def countStr = vars.get("fetchedIds_matchNr")
int count = countStr != null ? countStr.toInteger() : 0
def queue = props.get("usersQueue")

if (count > 0) {
    for (int i = 1; i <= count; i++) {
        queue.add(vars.get("fetchedIds_" + i))
    }
    log.info("=== Додано в чергу: " + count + " юзерів. Загалом у черзі: " + queue.size())
}

// Якщо Keycloak повернув менше 1000 юзерів (або 0) — ми дійшли до кінця, зупиняємо While Controller
if (count < 1000) {
    vars.put("keepFetching", "false")
    log.info("=== Збір завершено. Загальна кількість для видалення: " + queue.size())
}
----

****** *HTTP Header Manager*
+
Необхідно додати `HTTP Header Manager` як дочірній елемент до `Search users`, щоб передати токен авторизації.
+
*Content-Type:* `application/json`
+
*Authorization:* `Bearer ${access_token}`

[#while-controller]
==== While controller

Використовується для підтримки безперервного циклу виконання запитів, доки черга користувачів не стане порожньою.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[While Controller]

*Condition (function or variable):*

`${__groovy(vars.get('keepFetching') == 'true')}`

Цикл триватиме доти, доки локальна змінна потоку `keepFetching == true`.

* **Counter**
+
Цей елемент використовується для безпечного (thread‑safe) отримання індексу наступного користувача з глобальної черги. Кожен потік отримує своє значення лічильника, що дозволяє уникнути ситуацій, коли два потоки намагаються видалити одного й того ж користувача.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[Counter]
+
- *Starting value:* 0
+
Початкове значення лічильника: перша ітерація While Controller почне роботу з елемента черги з індексом 0.
+
- *Increment:* 1000
+
Значення, на яке збільшується лічильник після кожного використання. Інкремент 1000 гарантує, що кожен потік отримує свій унікальний діапазон індексів, навіть якщо виконується багато ітерацій.
+
- *Exported Variable Name:* offset
+
Змінна, в яку JMeter записує поточне значення лічильника.

* **Search users (HTTP Request)**
+
Виконує пошук користувачів у Keycloak за заданими параметрами, щоб отримати список облікових записів. Отримані ідентифікатори користувачів передаються на наступний етап сценарію — видалення.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[HTTP Request]
+
*Method:* `GET`
+
*Path:* `/auth/admin/realms/${officer_realm}/users`
+
*Follow redirects:* `true`
+
*Use KeepAlive:* `true`
+
У вкладці Parameters передаються:

- *search:* `perf-test-officer-`
+
Шукає всіх користувачів, у яких username починається з цього префікса.
+
- *first:* `${offset}`
+
Індекс першого користувача, з якого починається вибірка, генерується Counter‑ом, щоб кожен потік працював зі своєю частиною списку.
+
- *max:* `1000`
+
Максимальна кількість користувачів, яку Keycloak поверне за один запит.
+
- *briefRepresentation:* `true`
+
Повертає скорочену інформацію про користувачів, що зменшує навантаження на Keycloak і прискорює тест.
+

[TIP]
====
*Use KeepAlive* використовує постійне HTTP з’єднання, що зменшує затримки та навантаження.

*Follow redirects* дозволяє JMeter автоматично переходити за редіректами, якщо вони виникнуть.
====

[#SON-Extractor]
* **JSON Extractor**
+
JSON Extractor використовується для того, щоб витягнути всі ID користувачів з JSON, які були знайдені попереднім запитом Search users (HTTP Request).
+
**Отримання `списку ID користувачів`:**

- *Apply to:* `Main sample only`
+
Обробляється тільки основна відповідь HTTP-запиту.
+
- *Names of created variables:* `fetchedIds`
+
Це ім’я змінної, у яку JMeter збере всі знайдені ID.
- *JSON Path expressions:* `$[*].id`
+
Це шлях до всіх полів id у масиві JSON.
- *Match No. (0 for Random):* `-1`
+
Значення -1 означає витягнути всі збіги, а не один.

+

- Language: groovy
- Script:
+
[source,groovy]
----

int count = countStr != null ? countStr.toInteger() : 0

        queue.add(vars.get("fetchedIds_" + i))
    }
    log.info("=== Додано в чергу: " + count + " юзерів. Загалом у черзі: " + queue.size())
}

// Якщо Keycloak повернув менше 1000 юзерів (або 0) — ми дійшли до кінця, зупиняємо While Controller
if (count < 1000) {
    vars.put("keepFetching", "false")
    log.info("=== Збір завершено. Загальна кількість для видалення: " + queue.size())
}
----


* **HTTP Header Manager**
+
Необхідно додати `HTTP Header Manager` як дочірній елемент до `Search users`, щоб передати токен авторизації.
+
*Content-Type:* `application/json`
+
*Authorization:* `Bearer ${accessToken}`

* **Counter**
+
Створюється для ізоляції лічильника між різними етапами сценарію. Він не містить власних налаштувань, оскільки використовується як службовий контейнер для майбутнього розширення логіки.

[#thread-group]
=== Thread Group

Ця група потоків відповідає за паралельне вилучення ID користувачів з попередньо ініціалізованої черги та виконання запитів на їх видалення у Keycloak.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Threads (Users)] -> kbd:[Thread Group]

image:testing:jmeter-methodology/delete-keycloak-users/142101638.jpg[]

**Значення для Thread Group:**

* *Name:* `Thread Group`
* *Action to be taken after a Sample error:* `Continue`
** Виконання має продовжуватися, навіть якщо видалення конкретного користувача завершилося помилкою (наприклад, користувач вже не існує).
* *Number of Threads (users):* `50`
** Визначає кількість паралельних потоків для обробки черги.
* *Ramp-up period (seconds):* `10`
** Час, за який стартують усі 50 потоків.
* *Loop Count:* `1`
** Кожен потік виконує ітерацію один раз, оскільки зациклення керується внутрішнім елементом `While Controller`.

==== While Controller

Використовується для підтримки безперервного циклу виконання запитів, доки черга користувачів не стане порожньою.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[While Controller]

image:testing:jmeter-methodology/delete-keycloak-users/142102813.jpg[]

*Condition (function or variable):*

`${__groovy(props.get('usersQueue') != null && !props.get('usersQueue').isEmpty())}`

Цикл триватиме доти, доки черга `usersQueue` не порожня.

* **Get from queue (JSR223 Sampler)**
+
Цей скрипт відповідає за безпечне (thread-safe) вилучення наступного ID користувача з глобальної черги та передачу його у змінну потоку для подальшого використання у запиті на видалення.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[JSR223 Sampler]
+
*Language:* groovy
+
*Script:*
+
[source,groovy]
----
def queue = props.get("usersQueue")
if (queue != null) {
    def id = queue.poll() // Беремо і видаляємо з черги потокобезпечно
    if (id != null) {
        vars.put("idToDelete", id)
    } else {
        vars.put("idToDelete", "EMPTY")
    }
}

SampleResult.setIgnore()
----
+
[NOTE]
====
Метод `.poll()` вилучає та повертає елемент із голови черги. Якщо черга порожня, він повертає `null`. У такому випадку змінній `idToDelete` присвоюється значення `EMPTY`.
====

* **If Controller (Перевірка чи ID не порожнє)**
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[If Controller]
+
*Name*: If idToDelete is not empty
+
*Expression (must evaluate to true or false):*
+
`${__groovy(vars.get('idToDelete') != 'EMPTY')}`
+
*Evaluate for all children:* Зняти прапорець (перевірка виконується лише на вході в контролер).

** **If Controller (Перевірка токена)**
+
Цей контролер перевіряє, чи закінчився термін дії поточного токена доступу, і чи потрібно звернутися до Keycloak за новим.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[If Controller]
+
*Expression (must evaluate to true or false):*
+
`${__groovy(vars.get('tokenExpiry') == null || System.currentTimeMillis() > (vars.get('tokenExpiry') as long))}`
+
*Evaluate for all children:* Зняти прапорець (перевірка виконується лише на вході в контролер).
+
[TIP]
====
Вираз перевіряє дві умови: чи змінна `tokenExpiry` взагалі не існує (перша ітерація), або чи поточний системний час перевищив розрахований час смерті токена.
====

[#get-token-http-request]
==== HTTP Request (Отримання токена)
Запит до Keycloak Admin API для отримання токена доступу (Bearer Token) за допомогою client_credentials або іншого grant_type.

[#extract-access-token]
===== Get access token (Regular Expression Extractor)

Пост-процессор Regular Expression Extractor використовується для витягнення даних за регулярним виразом. Цей пост-процессор дозволяє витягувати дані з тіла відповіді, заголовків, URL, кода відповіді чи Response Message.

**Отримання `access_token`:**

- *Apply to:* `Main sample only`
- *Field to check:* `Body`
- *Name of created variable:* `access_token`
- *Regular Expression:* `access_token":"(.+?)"`
- *Template:* `$1$`
- *Match No.:* `1`
- *Default Value:* `not_found`

[#extract-expires-in]
===== expiresIn (JSON Extractor)
Оскільки відповідь повертається у форматі JSON, можна використати JSON Extractor, щоб зберегти час життя токена у локальні змінні потоку.

**Отримання `expiresIn`:**

- *Apply to:* `Main sample only`
- *Names of created variables:* `expiresIn`
- *JSON Path expressions:* `$.expires_in`
- *Default Values:* `300`

[#calculate-token-expiry-time]
===== Калькуляція терміну дії (JSR223 PostProcessor)
Keycloak повертає expires_in у секундах. Щоб потоки розуміли, коли саме токен "протухне" (і чи потрібно йти за новим), ми обчислюємо абсолютний Unix Timestamp часу його смерті.

- Language: groovy
- Script:
+
[source,groovy]
----
// Беремо секунди життя токена (з JSON Extractor)
long expiresInSec = vars.get("expiresIn").toLong()

// Розраховуємо час смерті токена (Поточний час + час життя мінус 30 секунд буфера)
long expiryTimestamp = System.currentTimeMillis() + (expiresInSec * 1000) - 30000

// Зберігаємо цей час у змінну для If Controller
vars.put("tokenExpiry", String.valueOf(expiryTimestamp))
----

[IMPORTANT]
Віднімання 30000 (30 секунд) є критичним буфером. Воно гарантує, що якщо запит на видалення почнеться за мить до реального закінчення дії токена, він не "протухне" в польоті через мережеві затримки.
