Цей документ описує технічний процес розробки та автоматизації сценарію навантажувального тестування для функціоналу "Реєстрація користувача (UNREGISTERED ROLE)" у Keycloak та взаємодії з порталом. Сценарій включає підготовку тестових даних (створення та видалення користувачів), авторизацію та виконання основного бізнес-процесу.

[#overview]
== Огляд сценарію
Мета цього сценарію — імітувати поведінку незареєстрованого користувача, який проходить процес авторизації, виконує певні дії на порталі та виходить із системи. Сценарій також включає підготовчі етапи для створення та видалення тестових користувачів.

Схема роботи сценарію:

. *Ініціалізація черги видалення:* Підготовка черги ID користувачів для видалення.
. *Пошук та збір ID користувачів:* Збір ID існуючих тестових користувачів для подальшого видалення.
. *Видалення користувачів:* Виконання `DELETE` запитів до Keycloak Admin API для очищення тестового середовища.
. *Створення користувачів:* Створення нових тестових користувачів у Keycloak.
. *Авторизація:* Проходження повного циклу авторизації на порталі.
. *Основний бізнес-процес:* Виконання запитів, що імітують дії користувача на порталі.
. *Вихід:* Завершення сесії користувача.

[#test-plan-setup]
=== Налаштування Test Plan

Для поточного сценарію буде використаний підхід з двома `setUp Thread Group`:

. Група потоків для ініціалізації черги для видалення користувачів з Keycloak
.. 1 потік, 1 сек (Ramp-up), 1 ітерація
. Група потоків для безпосереднього видалення користувачів
.. 50 потоків, 10 сек (Ramp-up), 1 ітерація
. Основна група потоків для навантажувального тесту

[IMPORTANT]
====
Оскільки працює два `setUp Thread Group`, JMeter їх запустить одночасно і вони будуть виконуватись паралельно. Щоб забезпечити виконання цих груп потоків чітко послідовно, необхідно в налаштуваннях `Test Plan` увімкнути опцію `*Run Thread Groups consecutively (i.e. one at a time)*`
====

[#http-request-defaults]
=== HTTP Request Defaults

*HTTP Request Defaults* — це конфігураційний елемент (Configuration Element) у JMeter, який виконує роль "глобального шаблону" для всіх HTTP-запитів.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[HTTP Request Defaults]

image:testing:jmeter-methodology/unregistered-role/142140643.jpg[]

**Як це працює:**

. *Сфера дії (Scope):* Елемент діє на всі запити, що знаходяться "під ним" або на тому ж рівні в дереві тест-плану.

. *Перевизначення (Override):* Якщо в самому HTTP Request вказати значення (наприклад, інший шлях /login замість дефолтного /), JMeter надасть пріоритет налаштуванням конкретного запиту, ігноруючи дефолтні.

**Значення для HTTP Request Defaults**

* *Protocol:* `${protocol}`
* *Server Name or IP:* `${keycloack_url}`
* *Port Number:* `${port}`

[TIP]
====
Завжди розміщуйте *HTTP Request Defaults* на рівні "*Test Plan*" (якщо налаштування стосуються всього тесту) або на рівні конкретної "*Thread Group*" (якщо потрібні різні налаштування для різних груп користувачів). Це найкращий спосіб уникнути "магічних значень", які потім важко знайти та виправити.
====

==== Init queue (JSR223 Sampler)

*JSR223 Sampler* — це елемент Apache JMeter, який виконує власний скриптовий код для генерації або обробки тестових даних. Він дуже універсальний і дозволяє імітувати логіку, яку неможливо обробити стандартними запитами.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[JSR223 Sampler]

image:testing:jmeter-methodology/unregistered-role/142142344.jpg[]

**Значення для Init queue:**

* *Name:* `Init queue`
* *Language:* `groovy`
* *Script:*
+
[source,groovy]
----
import java.util.concurrent.ConcurrentLinkedQueue
props.put("usersQueue", new ConcurrentLinkedQueue<String>())
vars.put("keepFetching", "true")
SampleResult.setIgnore()
----

[IMPORTANT]
====
Створюється `*ConcurrentLinkedQueue*` — потокобезпечна (thread-safe) черга для спільного використання між потоками JMeter.

[IMPORTANT]

`*props*` — це *глобальний scope* JMeter. Змінні в props: видимі всім Thread Group, доступні всім потокам, живуть протягом усього тесту.

[TIP]

`*vars.put("keepFetching", "true")*` — створюється звичайна локальна змінна потоку. Ця змінна потрібна для керування циклом, наприклад поки `keepFetching == true` -- цикл продовжується.

[#while-controller-fetch-users]
==== While Controller (Збір користувачів)

Використовується для циклічного збору ID користувачів з Keycloak, доки не будуть отримані всі користувачі, що відповідають критеріям пошуку.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[While Controller]

image:testing:jmeter-methodology/unregistered-role/142142543.jpg[]

*Condition (function or variable):*

`${__groovy(vars.get('keepFetching') == 'true')}`

Цикл триватиме доти, доки змінна `keepFetching` має значення `true`.

***** *Counter*
+
*Counter* — це конфігураційний елемент, який генерує послідовні числа, починаючи з заданого стартового значення. У цьому випадку він використовується для керування параметром `offset` при пагінації запитів до Keycloak.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[Counter]
+
image:testing:jmeter-methodology/unregistered-role/142142644.jpg[]
+
*Start:* `0`
+
*Increment:* `1000`
+
*Reference Name:* `offset`
+
*Track Counter Independently for each User:* `false`

***** *Search users (HTTP Request)*
+
Цей запит виконує пошук користувачів у Keycloak за певними критеріями та з використанням пагінації.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[HTTP Request]
+
image:testing:jmeter-methodology/unregistered-role/142142758.jpg[]
+
*Method:* `GET`
+
*Path:* `/auth/admin/realms/${realm}/users`
+
*Parameters:*
** `search`: `perf-test-citizen-` (префікс для пошуку тестових користувачів)
** `first`: `${offset}` (поточне зміщення для пагінації)
** `max`: `1000` (максимальна кількість користувачів за запит)
** `briefRepresentation`: `true` (отримати скорочене представлення користувачів)

****** *JSON Extractor (fetchedIds)*
+
*JSON Extractor* використовується для витягнення ID користувачів з JSON-відповіді.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Post-Processor] -> kbd:[JSON Extractor]
+
image:testing:jmeter-methodology/unregistered-role/142142906.jpg[]
+
*Names of created variables:* `fetchedIds`
+
*JSON Path expressions:* `$[*].id`
+
*Match No.:* `-1` (витягти всі відповідності)

****** *JSR223 PostProcessor (process fetchedIds)*
+
Цей *JSR223 PostProcessor* обробляє отримані ID користувачів, додає їх до глобальної черги `usersQueue` та перевіряє, чи потрібно продовжувати збір користувачів.
+
image:testing:jmeter-methodology/unregistered-role/142142951.jpg[]
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
def countStr = vars.get("fetchedIds_matchNr")
int count = countStr != null ? countStr.toInteger() : 0
def queue = props.get("usersQueue")

if (count > 0) {
    for (int i = 1; i <= count; i++) {
        queue.add(vars.get("fetchedIds_" + i))
    }
    log.info("Added to queue: " + count + " users. Total in queue: " + queue.size())
}

// If Keycloak returns < 1000 users (or 0) — this is finish, stop While Controller
if (count < 1000) {
    vars.put("keepFetching", "false")
    log.info("Collect finished. Total count for deleting: " + queue.size())
}
----

****** *HTTP Header Manager*
+
Необхідно додати `HTTP Header Manager` як дочірній елемент до `Search users`, щоб передати токен авторизації.
+
*Content-Type:* `application/json`
+
*Authorization:* `Bearer ${access_token}`

[#while-controller-delete-users]
==== While Controller (Видалення користувачів)

Використовується для підтримки безперервного циклу виконання запитів, доки черга користувачів не стане порожньою.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[While Controller]

*Condition (function or variable):*

`${__groovy(props.get('usersQueue') != null && !props.get('usersQueue').isEmpty())}`

Цикл триватиме доти, доки черга `usersQueue` не порожня.

***** *Extract id to delete (JSR223 Sampler)*
+
Цей скрипт відповідає за безпечне (thread-safe) вилучення наступного ID користувача з глобальної черги та передачу його у змінну потоку для подальшого використання у запиті на видалення.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[JSR223 Sampler]
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
def queue = props.get("usersQueue")
if (queue != null) {
    def id = queue.poll() // Thread-safe removing
    if (id != null) {
        vars.put("idToDelete", id)
    } else {
        vars.put("idToDelete", "EMPTY")
    }
}

SampleResult.setIgnore()
----
+
[NOTE]
====
Метод `.poll()` вилучає та повертає елемент із голови черги. Якщо черга порожня, він повертає `null`. У такому випадку змінній `idToDelete` присвоюється значення `EMPTY`.
====

***** *If idToDelete is not empty (If Controller)*
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[If Controller]
+
*Name*: `If idToDelete is not empty`
+
*Expression (must evaluate to true or false):*
+
`${__groovy(vars.get('idToDelete') != 'EMPTY')}`
+
*Evaluate for all children:* Зняти прапорець (перевірка виконується лише на вході в контролер).

****** *If Controller (Перевірка токена)*
+
Цей контролер перевіряє, чи закінчився термін дії поточного токена доступу, і чи потрібно звернутися до Keycloak за новим.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[If Controller]
+
*Expression (must evaluate to true or false):*
+
`${__groovy(vars.get('tokenExpiry') == null || System.currentTimeMillis() > (vars.get('tokenExpiry') as long))}`
+
*Evaluate for all children:* Зняти прапорець (перевірка виконується лише на вході в контролер).
+
[TIP]
====
Вираз перевіряє дві умови: чи змінна `tokenExpiry` взагалі не існує (перша ітерація), або чи поточний системний час перевищив розрахований час смерті токена.
====

******* *Get token (Module Controller)*
+
Якщо попередня умова (`If Controller`) виконується, викликається `Module Controller`, який перенаправляє виконання до існуючого `Test Fragment` для отримання нового токена.
+
Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Logic Controller] -> kbd:[Module Controller]
+
У вікні налаштувань необхідно розгорнути дерево тест-плану і вибрати цільовий `Test Fragment` -> `Get token`.

[#calculate-token-expiry-time]
===== Калькуляція терміну дії (JSR223 PostProcessor)
Keycloak повертає `expires_in` у секундах. Щоб потоки розуміли, коли саме токен "протухне" (і чи потрібно йти за новим), ми обчислюємо абсолютний Unix Timestamp часу його смерті.

- Language: `groovy`
- Script:
+
[source,groovy]
----
// Беремо секунди життя токена (з JSON Extractor)
long expiresInSec = vars.get("expiresIn").toLong()

// Розраховуємо час смерті токена (Поточний час + час життя мінус 30 секунд буфера)
long expiryTimestamp = System.currentTimeMillis() + (expiresInSec * 1000) - 30000

// Зберігаємо цей час у змінну для If Controller
vars.put("tokenExpiry", String.valueOf(expiryTimestamp))
----

[IMPORTANT]
Віднімання 30000 (30 секунд) є критичним буфером. Воно гарантує, що якщо запит почнеться за мить до реального закінчення дії токена, він не "протухне" в польоті через мережеві затримки.

*Language:* `groovy`

*Script:*

[source,groovy]
----
import java.net.URLDecoder;

String encoded = vars.get("redirectUriEncoded");

if (encoded != null && !encoded.equals("NOT_FOUND")) {
    String decoded = URLDecoder.decode(encoded, "UTF-8");
    vars.put("redirectUri", decoded);
    log.info("Decoded Redirect URI: " + decoded);
}

def cookieList = []
def lbCookie = ""
def headers = prev.getResponseHeaders().split("\n")

for (String header : headers) {
    if (header.toLowerCase().startsWith("set-cookie:")) {
        def matcher = (header =~ /(?i)set-cookie:\s*([^;\r\n]+)/)
        if (matcher.find()) {
            def cookieVal = matcher.group(1).trim()
            cookieList.add(cookieVal)

            // Якщо кука не починається з "session=", значить це Sticky Session балансувальника
            if (!cookieVal.toLowerCase().startsWith("session=")) {
                lbCookie = cookieVal
                vars.put("lbCookie", lbCookie)
                log.info("=== Збережено куку балансувальника: " + lbCookie)
            }
        }
    }
}

if (cookieList.size() > 0) {
    vars.put("allPortalCookies", cookieList.join("; "))
}
----

==== process-instances (HTTP Request)
Запит для отримання екземплярів процесів.

image:testing:jmeter-methodology/unregistered-role/145091658.jpg[]

*Method:* `GET`

*Path:* `api/runtime/process-instances`

*Parameters:*

** `offset`: `0`

** `limit`: `2`

** `sort`: `desc(startTime)`

***** *JSR223 PostProcessor (isAutoStart)*
+
Визначає, чи потрібно автоматично запускати новий процес, якщо існуючих екземплярів немає.
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import groovy.json.JsonSlurper

def slurp = { text ->
    new JsonSlurper().parseText(text.toString())
}

def data = slurp(prev.getResponseDataAsString())
def isAutoStart = data.size() == 0
vars.put('isAutoStart', isAutoStart as String)
----

***** *JSR223 - Clear Cookie*
+
Очищає куки та змінні сесії після виходу.

    log.warn("Cookie Manager не знайдено у цьому запиті!")

    sampler.getCacheManager().clear()
    log.info("=== [SESSION CLEAR] HTTP Cache Manager очищено ===")

vars.remove("xsrfToken")
vars.remove("authUrl")
vars.remove("state")
vars.remove("redirectUriEncoded")
vars.remove("redirectUri")
vars.remove("loginAction")
vars.remove("authCode")
vars.remove("portalSession")
vars.remove("allPortalCookies")
vars.remove("lbCookie")

log.info("=== [SESSION CLEAR] Змінні авторизації видалено. Готові до логіну Провайдера. ===")

****** *JSR223 PostProcessor*
+
Обробляє відповідь на створення користувача, встановлює `isUserCreated` або логує помилку.
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
if (prev.getResponseCode() == '201') {
    vars.put("isUserCreated", "true")
    def userName = vars.get("userName")
    log.info("User {} has been created", userName)
} else if (prev.getResponseCode() == '409') {
	vars.put("isUserCreated", "true")
	log.info("Conflict: {}", prev.getResponseDataAsString())
	ctx.setRestartNextLoop(true)
} else {
    log.warn("Помилка створення юзера. Чекаємо 3 сек і пробуємо знову...")
    Thread.sleep(3000)
}
----

****** *Put roles (JSR223 PostProcessor)*
+
Обробляє JSON-відповідь та вибирає ролі для призначення.
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import groovy.json.*

def roles = prev.getResponseDataAsString()
def data = new JsonSlurper().parseText(roles.replaceAll("\\\\n", ""))
def role = vars.get('role')

def user_roles = data.findAll { it.name == role || it.name == 'citizen' }

if (user_roles) {
    vars.put("user_roles", JsonOutput.toJson(user_roles))
} else {
    log.info("user_roles not found")
}
----
