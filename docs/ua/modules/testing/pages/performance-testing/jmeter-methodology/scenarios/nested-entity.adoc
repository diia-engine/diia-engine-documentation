include::platform:ROOT:partial$templates/document-attributes/default-set-ua.adoc[]

:sectlinks:

Цей документ описує технічний процес розробки та автоматизації сценарію навантажувального тестування для функціоналу "Вкладена сутність" (Nested Entity) на офіцерському порталі. Сценарій імітує повний життєвий цикл обробки бізнес-процесу, що включає кілька кроків, завантаження файлів та взаємодію з формами.

[#overview]
== Огляд сценарію
Мета цього сценарію — імітувати поведінку офіцера, який проходить повний бізнес-процес, що складається з декількох кроків, кожен з яких може включати заповнення форм, завантаження файлів та підписання.

Схема роботи сценарію:

. *Ініціалізація:* Налаштування глобальних змінних та функцій.
. *Авторизація:* Проходження повного циклу авторизації на офіцерському порталі.
. *Ініціація бізнес-процесу:* Запуск нового екземпляра бізнес-процесу.
. *Покрокова обробка:* Виконання послідовних кроків бізнес-процесу, включаючи заповнення форм, завантаження файлів та завершення завдань.
. *Вихід:* Завершення сесії користувача.

=== CSV Data Set Config (Users Data)

*CSV Data Set Config* — це конфігураційний елемент JMeter, який дозволяє читати дані з CSV-файлу та використовувати їх як змінні у тест-плані. Це дозволяє легко параметризувати запити, використовуючи різні набори даних для кожного потоку або ітерації.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[CSV Data Set Config]

image:testing:jmeter-methodology/nested-entity/145102016.jpg[]

**Значення для CSV Data Set Config:**

* *Filename:* `${testDataDir}/nested-entity-execution-plan.csv`
* *File Encoding:* (порожнє, використовується системне)
* *Delimiter:* `,`
* *Variable Names:* `userName,lastName,firstName,secondName,birthday,orderType,orderNumber,orderDate,file`
* *Ignore first line:* `false` (оскільки файл не містить заголовка)
* *Allow quoted data:* `false` (значення в лапках не обробляються спеціально)
* *Recycle on EOF:* `false` (не починати знову після закінчення файлу)

* *Sharing Mode:* `All threads` (кожен потік отримує унікальні дані)

***** *JSR223 - Decode URI*
+
Цей *JSR223 PostProcessor* декодує `redirect_uri` та зберігає куки балансувальника навантаження (`lbCookie`) та всі куки порталу (`allPortalCookies`).
+
image:testing:jmeter-methodology/nested-entity/145112704.jpg[]
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import java.net.URLDecoder;

String encoded = vars.get("redirectUriEncoded");

if (encoded != null && !encoded.equals("NOT_FOUND")) {
    String decoded = URLDecoder.decode(encoded, "UTF-8");
    vars.put("redirectUri", decoded);
    log.info("Decoded Redirect URI: " + decoded);
}

def cookieList = []
def lbCookie = ""
def headers = prev.getResponseHeaders().split("\n")

for (String header : headers) {
    if (header.toLowerCase().startsWith("set-cookie:")) {
        def matcher = (header =~ /(?i)set-cookie:\s*([^;\r\n]+)/)
        if (matcher.find()) {
            def cookieVal = matcher.group(1).trim()
            cookieList.add(cookieVal)

            // Якщо кука не починається з "session=", значить це Sticky Session балансувальника
            if (!cookieVal.toLowerCase().startsWith("session=")) {
                lbCookie = cookieVal
                vars.put("lbCookie", lbCookie)
                log.info("=== Збережено куку балансувальника: " + lbCookie)
            }
        }
    }
}

if (cookieList.size() > 0) {
    vars.put("allPortalCookies", cookieList.join("; "))
}
----

* *Field to check:* `Response Headers`

* *Regular Expression:* `XSRF-TOKEN=([^;\r\n]+)`
* *Template:* `$1$`

***** *JSR223 PostProcessor (Set XSRF Token)*
+
Цей *JSR223 PostProcessor* оновлює `XSRF-TOKEN` у `Cookie Manager`, якщо він був витягнутий. Це гарантує, що наступні запити будуть використовувати актуальний токен.
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import org.apache.jmeter.protocol.http.control.Cookie
import org.apache.jmeter.protocol.http.control.CookieManager
import java.time.Instant
import java.time.temporal.ChronoUnit

def xsrf = vars.get("xsrfToken")

if(xsrf != null && xsrf != "NO_TOKEN" && xsrf != "EMPTY") {
    long futureExpiry = Instant.now().plus(1, ChronoUnit.HOURS).getEpochSecond()
    def cookie = new Cookie("XSRF-TOKEN", xsrf, vars.get("host"), "/", true, futureExpiry)

    // Спробуємо отримати CookieManager з поточного запиту
    def cookieManager = sampler.getCookieManager()

    // Якщо його немає в запиті, беремо його з потоку (Thread Context)
    if (cookieManager == null) {
        cookieManager = ctx.getCurrentSampler().getCookieManager()
    }

    // Якщо ми його знайшли — додаємо куку
    if (cookieManager != null) {
        cookieManager.add(cookie)
        log.info("=== [COOKIE MANAGER] XSRF-TOKEN додано успішно: " + xsrf)
    } else {
        log.warn("=== [УВАГА] Cookie Manager не знайдено навіть у контексті потоку!")
        // Якщо менеджера немає, просто зберігаємо в змінну
    }
}

+

***** *Create payload (JSR223 Sampler)*
+
Цей *JSR223 Sampler* створює JSON-об'єкт (`payload`) для відправки даних форми, оновлюючи деякі поля з CSV-файлу.
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import groovy.json.JsonOutput

def formData = extractVar('formData')?.data
log.info('formData={}', formData)

def payload = [:]
payload.data = formData
payload.data.birthday = vars.get('birthday')
payload.data.order_date = vars.get('orderDate')
vars.put('payload', JsonOutput.toJson(payload))
log.info("Payload={}", JsonOutput.toJson(payload))

def extractVar(String varName) {
	def tmp = vars.get(varName)
	if (tmp == 'NOT_FOUND') return null
	log.info('{}={}', varName, tmp)
	def slurp = props.get('slurp')
	return slurp(tmp)
}
