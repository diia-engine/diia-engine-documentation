= Сценарій "Перегляд великих масивів даних"
include::platform:ROOT:partial$templates/document-attributes/default-set-ua.adoc[]

:sectlinks:

Цей документ описує технічний процес розробки та автоматизації сценарію навантажувального тестування для функціоналу "Перегляд великих масивів даних". Сценарій імітує поведінку користувача, який авторизується, переходить на сторінку з Edit Grid та читає дані з неї, після чого виконується submit форми.

[#overview]
== Огляд сценарію
Мета цього сценарію — імітувати поведінку користувача, який створює навантаження на сервіс form-submission-validation.

Схема роботи сценарію:

. *Ініціалізація:* Налаштування глобальних змінних та функцій.
. *Авторизація:* Проходження повного циклу авторизації на офіцерському порталі.
. *Основний процес:* Старт бізнес-процесу, генерація даних Edit Grid, submit форми та повторне читання списку задач.
. *Вихід:* Завершення сесії користувача.

[#csv-users-data]
=== CSV - Users Data (CSV Data Set Config)

*CSV Data Set Config* — це конфігураційний елемент JMeter, який дозволяє читати дані з CSV-файлу та використовувати їх як змінні у тест-плані. Це дозволяє легко параметризувати запити, використовуючи різні набори даних для кожного потоку або ітерації.

Додати елемент слід натиснувши kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[CSV Data Set Config]

image:testing:jmeter-methodology/read-grid/145143410.jpg[]

**Значення для CSV Data Set Config:**

* *Filename:* `${testDataDir}/mock-users.csv`
* *File Encoding:* (порожнє, використовується системне)
* *Delimiter:* `,`
* *Variable Names:* `userName,fullname,edrpou,drfo`
* *Ignore first line:* `true`
* *Recycle on EOF:* `false` (не починати знову після закінчення файлу)
* *Stop Thread on EOF:* `true` (зупинити потік, коли дані закінчаться)
* *Sharing Mode:* `All threads` (кожен потік отримує унікальні дані)

Ця група потоків відповідає за виконання основного сценарію навантаження, включаючи авторизацію, перегляд таблиці та вихід із системи.

**Значення для TG_Test:**

* *Name:* `TG_Test`
* *Action to be taken after a Sample error:* `Start next loop`
** Якщо якийсь запит завершився помилкою, поточний потік переходить до наступної ітерації.
* *Number of Threads (users):* `${threads}`
** Визначає кількість паралельних потоків, що імітують користувачів. Значення береться зі змінної `threads`.
* *Ramp-up period (seconds):* `${rampUp}`
** Час, за який стартують усі потоки. Значення береться зі змінної `rampUp`.
* *Same user on next iteration:* `true`
** Потік зберігає прив'язку до того самого користувача між ітераціями, хоча в цьому сценарії налаштована одна ітерація.
* *Loop Count:* `1`
** Кожен потік виконує одну ітерацію сценарію для поточного рядка CSV.

|===

[cols="1,1", options="header"]
|===
| Name | Value
| `X-XSRF-TOKEN` | `${xsrfToken}`

** *JSR223 PreProcessor*
+
Цей *JSR223 PreProcessor* оновлює `xsrfToken` у змінних JMeter перед виконанням `start`, витягуючи актуальне значення з `Cookie Manager`. Такий синхронізатор потрібний для POST-запитів, де заголовок `X-XSRF-TOKEN` має відповідати cookie `XSRF-TOKEN`.
+
image:testing:jmeter-methodology/read-grid/145150216.jpg[]
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import org.apache.jmeter.protocol.http.control.CookieManager

CookieManager manager = sampler.getCookieManager()
if (manager != null) {
    for (int i = 0; i < manager.getCookieCount(); i++) {
        if (manager.get(i).getName().equals("XSRF-TOKEN")) {
            def latestToken = manager.get(i).getValue()
            vars.put("xsrfToken", latestToken)
            log.info("=== [XSRF SYNC] Оновлено токен із Cookie Manager: " + latestToken)
            break
        }
    }
} else {
    log.warn("Cookie Manager не знайдено!")
}
----

* *Create payload (JSR223 Sampler)*
+
JSR223 Sampler формує JSON payload для Edit Grid. Кількість рядків береться зі змінної `recordsCount`, а згенерований JSON записується у змінну `${payload}`. Виклик `SampleResult.setIgnore()` виключає службовий sampler з метрик як бізнес-запит.
+
*Language:* `groovy`
+
[source,groovy]
----
import org.apache.commons.lang3.RandomStringUtils
import groovy.json.JsonOutput

def editgridLatest = []
def recordsCount = vars.get('recordsCount') as Integer

for (int i = 0; i < recordsCount; i++) {
    def bookName = RandomStringUtils.randomAlphabetic(10).toLowerCase()
    def randomNumber = Integer.parseInt(RandomStringUtils.randomNumeric(4))

    def entry = [
    textfieldLatest: bookName,
    numberLatest: randomNumber
    ]
    editgridLatest << entry
}

def data = [editgridLatest: editgridLatest]
def payload = [data: data]
vars.put('payload', JsonOutput.toJson(payload))

SampleResult.setIgnore()
----
