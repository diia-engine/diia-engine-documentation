= Сценарій "Процес роботи з файлами (завантаження файлів від користувача)"

:sectlinks:

Цей документ описує технічний процес розробки та автоматизації сценарію навантажувального тестування для функціоналу "Процес роботи з файлами (завантаження файлів від користувача)". Сценарій імітує повний життєвий цикл обробки бізнес-процесу, що включає ініціацію процесу, завантаження трьох файлів, завершення першого завдання та завершення наступного завдання з даними форми.

[#overview]
== Огляд сценарію
Мета цього сценарію — імітувати поведінку офіцера, який проходить бізнес-процес, що вимагає завантаження кількох файлів до завершення завдання.

Схема роботи сценарію:

. *Ініціалізація:* Налаштування глобальних змінних та функцій.
. *Авторизація:* Проходження повного циклу авторизації на офіцерському порталі.
. *Ініціація бізнес-процесу:* Запуск нового екземпляра бізнес-процесу.
. *Завантаження файлів:* Завантаження трьох файлів, пов'язаних із першим завданням.
. *Завершення першого завдання:* Формування JSON payload з ідентифікаторами завантажених файлів та завершення завдання.
. *Завершення другого завдання:* Отримання наступного завдання, повторне використання даних форми та завершення процесу.
. *Вихід:* Завершення сесії користувача.

Завдяки цьому *Grafana* не показує кожен тест як окрему історію, а збирає їх разом під одним ідентифікатором (`application`).

[#csv-users-data]
=== CSV Data Set Config (Users Data)

*CSV Data Set Config* — це конфігураційний елемент JMeter, який дозволяє читати дані з CSV-файлу та використовувати їх як змінні у тест-плані. Це дозволяє легко параметризувати запити, використовуючи різні набори даних для кожного потоку або ітерації.

Елемент додається через kbd:[Edit] -> kbd:[Add] -> kbd:[Config Element] -> kbd:[CSV Data Set Config]

image:testing:jmeter-methodology/file-upload/145152617.jpg[]

**Значення для CSV Data Set Config:**

* *Filename:* `${testDataDir}/mock-users.csv`
* *File Encoding:* (порожнє, використовується системне)
* *Delimiter:* `,`
* *Variable Names:* `userName,fullName,edrpou,drfo`
* *Ignore first line:* `false` (оскільки файл не містить заголовка)
* *Allow quoted data:* `false` (значення в лапках не обробляються спеціально)
* *Recycle on EOF:* `false` (не починати знову після закінчення файлу)
* *Stop Thread on EOF:* `true` (зупинити потік, коли дані закінчаться)
* *Sharing Mode:* `All threads` (кожен потік отримує унікальні дані)

*setUp Thread Group* у JMeter виконується *один раз перед запуском основних Thread Group* і використовується для підготовчих операцій. У цьому сценарії він відповідає за ініціалізацію глобальної функції `slurp` для обробки JSON.

Елемент додається через kbd:[Edit] -> kbd:[Add] -> kbd:[Threads (Users)] -> kbd:[setUp Thread Group]

image:testing:jmeter-methodology/file-upload/145154053.jpg[]

**Значення для setUp Thread Group:**

* *Name:* `setUp Thread Group`
* *Action to be taken after a Sample error:* `Continue`
** Помилки не зупиняють підготовчий етап.
* *Number of Threads (users):* `1`
** Виконується одним потоком.
* *Ramp-up period (seconds):* `1`
** Швидкий старт.
* *Loop Count:* `1`
** Виконується лише один раз.

[#create-slurp-sampler]
==== Create slurp (JSR223 Sampler)

Цей *JSR223 Sampler* створює глобальну функцію `slurp` (використовуючи `JsonSlurper` з Groovy), яка дозволяє легко парсити JSON-рядки. Ця функція зберігається у `props` (глобальні властивості JMeter), що робить її доступною для всіх потоків та Test Fragment-ів.

Елемент додається через kbd:[Edit] -> kbd:[Add] -> kbd:[Sampler] -> kbd:[JSR223 Sampler]

image:testing:jmeter-methodology/file-upload/145154150.jpg[]

**Значення для Create slurp:**

* *Name:* `Create slurp`
* *Language:* `groovy`
* *Script:*
+
[source,groovy]
----
import groovy.json.JsonSlurper

def slurp = { text ->
    new JsonSlurper().parseText(text.toString())
}

props.put('slurp', slurp)
SampleResult.setIgnore()
----

Цей *JSR223 PreProcessor* оновлює `xsrfToken` у змінних JMeter, витягуючи його з `Cookie Manager`. Це необхідно, оскільки XSRF токен може змінюватися після деяких запитів.
+
image:testing:jmeter-methodology/file-upload/145155011.jpg[]
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import org.apache.jmeter.protocol.http.control.CookieManager

CookieManager manager = sampler.getCookieManager()
if (manager != null) {
    for (int i = 0; i < manager.getCookieCount(); i++) {
        if (manager.get(i).getName().equals("XSRF-TOKEN")) {
            def latestToken = manager.get(i).getValue()
            vars.put("xsrfToken", latestToken)
            log.info("=== [XSRF SYNC] Оновлено токен із Cookie Manager: " + latestToken)
            break
        }
    }
} else {
    log.warn("Cookie Manager не знайдено!")
}

****** *Set XSRF Token (JSR223 PostProcessor)*
+
Цей *JSR223 PostProcessor* створює cookie `XSRF-TOKEN` з отриманого значення та додає його до `Cookie Manager`. Якщо `Cookie Manager` недоступний через sampler, значення зберігається у змінній `xsrfToken`.
+
*Language:* `groovy`
+
*Script:*
+
[source,groovy]
----
import org.apache.jmeter.protocol.http.control.Cookie
import org.apache.jmeter.protocol.http.control.CookieManager
import java.time.Instant
import java.time.temporal.ChronoUnit

def xsrf = vars.get("xsrfToken")
long futureExpiry = Instant.now().plus(1, ChronoUnit.HOURS).getEpochSecond()
def cookie = new Cookie("XSRF-TOKEN", xsrf, vars.get("host"), "/", true, futureExpiry)
def cookieManager = sampler.getCookieManager()
if (cookieManager == null) {
	cookieManager = ctx.getCurrentSampler().getCookieManager()
}
if (cookieManager != null) {
	cookieManager.add(cookie)
     log.info("=== [COOKIE MANAGER] XSRF-TOKEN додано успішно: " + xsrf)
} else {
log.warn("=== [УВАГА] Cookie Manager не знайдено навіть у контексті потоку!")
	vars.put('xsrfToken', xsrf)
}
