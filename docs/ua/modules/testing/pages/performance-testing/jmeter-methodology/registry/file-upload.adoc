Цей розділ описує налаштування регламенту реєстра для проведення навантажувального тестування процесу завантаження масиву файлів від користувача (наприклад, статутних документів, скан-копій тощо).

[#liquibase]
== Вимоги до моделі даних (Liquibase)

Для збереження інформації про завантажені файли використовується таблиця `laboratory_with_multiple_file`.

[NOTE]
====
Зверніть увагу на використання спеціального типу `type_file[]` для колонки `files`. Цей тип дозволяє базі даних коректно зберігати масив посилань (ідентифікаторів) на фізичні файли у сховищі Ceph/S3.
====

.Таблиця `laboratory_with_multiple_file` (data-model/laboratory_with_multiple_file/tables.xml)
[source,xml]
----
<changeSet id="create table laboratory_with_multiple_file" author="registry owner">
    <createTable tableName="laboratory_with_multiple_file" ext:historyFlag="true" remarks="Лабораторії що атестуються">
        <column name="laboratory_with_multiple_file_id" type="UUID" defaultValueComputed="uuid_generate_v4()">
            <constraints nullable="false" primaryKey="true" primaryKeyName="pk_laboratory_with_multiple_file_id"/>
        </column>
        <column name="name" type="TEXT">
            <constraints nullable="false"/>
        </column>
        <column name="files" type="type_file[]" remarks="Масив файлів"/>
    </createTable>
</changeSet>
----

[#file-handling]
== Робота з файлами у JMeter

Самі тестові файли (PDF, зображення тощо) не генеруються автоматично під час тесту, а заздалегідь **розміщуються в директорії разом із `jmx` тестами**. Скрипт використовуватиме їх для формування `multipart/form-data` запитів до API Платформи.

[WARNING]
====
При масовому тестуванні завантаження файлів критично важливо слідкувати за **споживанням оперативної пам'яті (RAM)** агентами.
Оскільки JMeter завантажує файли в пам'ять під час формування запиту, використовуйте оптимізовані невеликі файли-заглушки (по кілька кілобайт), якщо мета тесту — перевірка логіки збереження, а не пропускної здатності мережі. Це запобігатиме падінню контейнерів агента з помилкою `OutOfMemoryError`.
====

* `feature-sign-object-file`

[#integration-prerequisites]
== Інтеграційні передумови та пайплайн

Пайплайн підготовки до запуску навантаження залишається незмінним і виконує сувору послідовність кроків:

1. **Генерація тестових даних (Gradle):** Генерація пулу чиновників (officers).
xref:testing:performance-testing/jmeter-methodology/pipelines.adoc#pipeline-data-generation[Генерація тестових даних через Gradle та Groovy]

2. **Оновлення мок-сервісу:** Патчинг `ConfigMap` мок-сервісу.
xref:testing:performance-testing/jmeter-methodology/pipelines.adoc#pipeline-patch-configmap[Patch ConfigMap у тестовому середовищі]

3. **Очищення середовища Keycloak (JMeter):** Видалення існуючих тестових користувачів.
xref:testing:performance-testing/jmeter-methodology/pipelines.adoc#jmxdeletekeyclokofficers-task[jmxDeleteKeycloakOfficers]

4. **Створення користувачів у Keycloak (JMeter):** Масове створення нових чиновників у Keycloak.
xref:testing:performance-testing/jmeter-methodology/pipelines.adoc#jmxdeletekeyclokofficers-task[jmxCreateKeycloakOfficers]

5. **Запуск головного тесту:** Виконання JMX-сценарію, який імітує проходження бізнес-процесу та завантаження масиву файлів.
xref:testing:performance-testing/jmeter-methodology/pipelines.adoc#pipeline-jmeter-run[Запуск основного JMeter Test Plan]

== Конфігурація бізнес-процесів та RBAC доступ

Регламент повинен мати налаштовану дефініцію процесу та відповідні права доступу для рольової моделі:

[cols="1,1", options="header"]
|===
| Параметр | Значення
| Process Definition ID | `feature-multiple-file-saving`
| Process Definition Name | `Завантаження масиву файлів`
2+| RBAC
| bp-auth/officer.yml | `op-regression`
|===

[#rbac-setup]
=== Налаштування RBAC

Правила авторизації для чиновників повинні бути задекларовані у файлі `bp-auth/officer.yml` наступним чином:

[source,yaml]
----
authorization:
  realm: 'officer'
  process_definitions:
    - process_definition_id: "feature-multiple-file-saving"
      process_name: "Завантаження масиву файлів"
      process_description: "Завантаження масиву файлів"
      roles:
        - 'op-regression'
----

====
Використовуйте файл _link:{attachmentsdir}/jmeter-methodology/feature-multiple-file-saving.bpmn[feature-multiple-file-saving.bpmn]_ із готовою схемою бізнес-процесу для прикладу.
